# Ecosystem research — Claude Code enhancement frameworks (July 2026)

Research input for galaxy-brain: a verification-first engineering harness (adversarial evaluator, generator != evaluator, test-first, full-suite gates, never auto-merge, spec-driven build on GitHub Spec Kit).

## Competitor snapshot

**SuperClaude** — MIT-licensed config framework injecting behavioral instructions into Claude Code: ~24 `/sc:` commands, 14 agents/personas, 6 modes, 6 MCP integrations ([review](https://vibecodinghub.org/blog/superclaude-review), [codex fork](https://github.com/modelcontextprotocol-codex/SuperClaude_Framework_Codex)). Strengths: broad opinionated workflow coverage (plan/implement/test/review); namespaced commands avoid conflicts. Criticisms: it is prompt-injection only (no deterministic enforcement), and its always-loaded instruction mass plus stacked MCP servers eat context — 5-6 MCP integrations can consume 30-50% of the window before the first prompt ([MCP context-killer analysis](https://dev.to/steve_oak/mcp-was-a-context-killer-claude-code-just-fixed-it-55o0), [token optimization](https://buildtolaunch.substack.com/p/claude-code-token-optimization)).

**claude-flow / Ruflo** — swarm orchestrator (now Rust/WASM "Ruflo" with Raft/Byzantine consensus branding) ([history](https://dev.to/stevengonsalvez/claude-flow-the-multi-agent-swarm-orchestrator-before-it-got-a-new-name-4kd4)). Strengths: pioneered multi-agent topologies and hive-mind memory vocabulary; huge mindshare. Criticisms: an audit found ~85% of its 300+ MCP tools are mocks/stubs returning fake success and "fake but realistic-looking metrics" ([issue #653](https://github.com/ruvnet/ruflo/issues/653), [audit gist](https://gist.github.com/roman-rr/ed603b676af019b8740423d2bb8e4bf6)); independent evaluation measured +163% cost, +203% input tokens, 0 tool invocations vs baseline ([issue #1748](https://github.com/ruvnet/ruflo/issues/1748)). Also squeezed by Anthropic's Feb-2026 official Agent Teams and an Apr-2026 policy limiting Pro/Max subscriptions in third-party orchestrators ([landscape](https://claudefa.st/blog/tools/orchestrators/multi-agent-orchestrators)).

**BMAD Method** — agile-simulation framework: 19+ role agents (Analyst, PM, Architect, SM, Dev, QA) produce PRD/architecture docs, then "context-engineered" story files drive the Dev agent ([guide](https://www.augmentcode.com/guides/bmad-method-ai-development), [repo issues](https://github.com/bmad-code-org/BMAD-METHOD/issues/1628)). Strengths: story files that carry full implementation context are genuinely effective; strong planning discipline. Criticisms: steep learning curve (CLI + YAML + 19 agent handoffs); inter-agent drift — Architect contradicts PM, patched with manual handoff checklists ([explainer](https://codemyspec.com/blog/bmad-method-explained)).

**Plugin marketplaces / awesome lists** — official marketplace (~100-200 curated plugins) plus ~2,500 discoverable across 192 community marketplaces; 9,000+ plugins total across hubs ([curated list](https://designrevision.com/blog/awesome-claude-code-plugins), [awesome-claude-plugins](https://github.com/Chat2AnyLLM/awesome-claude-plugins)). Top installs: Frontend Design (~829k), **Superpowers** (~752k), Context7 (~348k). Popular categories: skills/methodology packs, memory, code review, LSP/language servers, context management. Notable: **Superpowers** (obra) — composable auto-triggering skills enforcing TDD red-green, root-cause debugging, two-stage review ([repo](https://github.com/obra/superpowers)); **claude-mem** — 72k-star memory plugin, hook-based capture -> AI compression -> typed observations in SQLite, three-tier relevance retrieval ([repo](https://github.com/thedotmack/claude-mem)); **code-review-graph** — 49x token reduction via graph-scoped review ([writeup](https://www.innovatrixinfotech.com/blog/code-review-graph-claude-code-token-usage-reduction)); **adversarial-review** — dual Optimizer/Skeptic agents, only findings surviving cross-challenge get fixed, bounded verification loop ([repo](https://github.com/ng/adversarial-review)); **Codex plugin** — official cross-vendor adversarial review, Claude<->Codex ([writeup](https://www.ai.joaoqueiros.com/blog/codex-plugin-claude-code-adversarial-review-workflow)); **Claude Code Harness** — contract-first Plan->Work->Review->Release with per-stage human gates and evidence packaging, ~1.7k stars ([repo](https://github.com/Chachamaru127/claude-code-harness), [analysis](https://alphasignalai.substack.com/p/how-claude-code-harness-turns-agent)).

**GitHub Spec Kit** — spec-driven toolkit (constitution -> specify -> clarify -> plan -> tasks -> implement), 30+ agent integrations, ~111k stars as of June 2026 ([docs](https://github.github.com/spec-kit/)). Now has a three-tier customization stack: extensions (new commands + `hooks.after_constitution`-style hooks in `.specify/extensions.yml`), presets (`preset.yml` template overrides: replace/prepend/append/wrap), and project-local overrides ([presets issue #1708](https://github.com/github/spec-kit/issues/1708), [upgrade docs](https://github.com/github/spec-kit/blob/main/docs/upgrade.md)). Strengths: massive adoption; clean phase separation with reviewable artifacts. Criticisms: heavy process whose documents govern "by convention rather than enforcement"; "illusion of work — generating a bunch of text" ([discussion #1784](https://github.com/github/spec-kit/discussions/1784)); overhead exceeds return on small features ([review](https://vibecoding.app/blog/spec-kit-review)).

## Ideas worth adopting

- **Hooks as guarantees, prompts as requests** — from the 2026 hooks consensus ([hooks explained](https://joseparreogarcia.substack.com/p/claude-code-hooks-explained-the-missing), [RFC #45427](https://github.com/anthropics/claude-code/issues/45427)). Every galaxy-brain gate (full suite green, no auto-merge, evaluator sign-off) should be a PreToolUse/Stop hook or script check, never a prompt instruction. This is the single biggest differentiator vs SuperClaude/BMAD.
- **Cross-challenge before fix** (adversarial-review): two independent reviewers must both sustain a finding under mutual challenge before it becomes actionable; fixes re-enter a bounded verification loop. Directly strengthens the generator!=evaluator loop and cuts false-positive churn.
- **Cross-vendor evaluator** (Codex plugin pattern): route evaluation to a different model *vendor*, not just a different instance — blind spots are model-family-correlated. galaxy-brain already wants generator!=evaluator; make the evaluator model pluggable.
- **Evidence packaging per release** (Claude Code Harness): every PR ships a machine-checkable evidence bundle (spec ref, failing-then-passing test log, full-suite result, review verdict). Turns "verified" from a claim into an artifact.
- **Story-file context injection** (BMAD): compile spec+plan+conventions into one self-contained task file per implementation unit, so implementer subagents start with zero exploration. Best surviving idea from BMAD without its 19-agent overhead.
- **Auto-triggering composable skills** (Superpowers): small skills with trigger descriptions instead of one mega-prompt; workflow phases activate contextually. Keeps per-turn context lean and is the top-installed methodology plugin's core mechanic.
- **Build on Spec Kit's extension/preset layer** rather than forking: ship galaxy-brain's verification phase as a Spec Kit extension command + preset overriding `implement`, keeping upstream compatibility ([#1708](https://github.com/github/spec-kit/issues/1708)).
- **Typed, compressed memory** (claude-mem): persist loop state as typed observations (finding, decision, verdict) retrieved by relevance, not raw transcripts — cheap recall across loop iterations.
- **Scoped review context** (code-review-graph): feed the evaluator only the dependency-graph slice of the change, not the diff + whole repo; 49x token reduction claims aside, scoping review input is the right default.

## Anti-patterns to avoid

- **Prompt-only enforcement**: Spec Kit's own top criticism — documents govern by convention, model drifts anyway ([#1784](https://github.com/github/spec-kit/discussions/1784)). Any rule not enforced by a hook/script will eventually be violated.
- **Always-loaded instruction mass**: SuperClaude-style frameworks front-load tens of KB of personas/commands; combined with MCP schemas this can burn 30-72% of the window before work starts. Load per-phase, on trigger.
- **Theater metrics / mock tooling**: claude-flow shipped hundreds of tools that returned fake success ([#653](https://github.com/ruvnet/ruflo/issues/653)). Never report a gate as passed without executing the real command and capturing real output.
- **Role proliferation**: BMAD's 19 agents create handoff drift and a steep learning curve; each agent boundary is a place where context is lost. Keep to the minimum roles the verification loop needs (finder/tester/fixer/evaluator).
- **Swarm-for-its-own-sake**: independent evals showed orchestration overhead (+163% cost) with zero tool value ([#1748](https://github.com/ruvnet/ruflo/issues/1748)); parallelism must be justified by isolated, verifiable work units (worktrees), not topology branding.
- **Process weight on small changes**: Spec Kit criticism — full ceremony on a one-line fix destroys adoption. Provide a fast path with the same gates but skippable artifact ceremony.
- **Trusting hooks absolutely**: hooks fail silently, can be bypassed by subagents, and settings can be edited by the model ([RFC #45427](https://github.com/anthropics/claude-code/issues/45427)). Put final gates *outside* the agent: CI checks and branch protection (never auto-merge = a GitHub setting, not a promise).

## Distribution patterns

- **Standard shape**: git repo with `.claude-plugin/marketplace.json` catalog + per-plugin `plugin.json`; install via `/plugin marketplace add owner/repo` then `/plugin install name@marketplace` ([docs](https://code.claude.com/docs/en/plugin-marketplaces)). Superpowers and claude-mem both use a personal marketplace repo.
- **Explicit semver in plugin.json**: version field is optional but load-bearing — without it every git push becomes a release (commit SHA = version); successful teams pin semver and bump deliberately ([deep dive](https://ice-ice-bear.github.io/posts/2026-04-03-claude-code-plugin-marketplace/)).
- **Catalog/plugin independence**: one marketplace.json can reference plugins across repos, pinned to branches/commits — catalog evolves separately from plugin code ([mpt.solutions](https://www.mpt.solutions/your-claude-plugin-marketplace-needs-more-than-a-git-repo/)). Use git/GitHub URL sources; relative paths silently fail for URL-added marketplaces.
- **Discoverability**: list on awesome-claude-plugins repos and hubs (claudepluginhub, claude-plugins.dev, aitmpl.com); the official directory shows install counts, and top plugins (Superpowers 752k installs) grew via a single memorable README pitch + one-command install.
- **claude-mem's cadence as benchmark**: 259 releases in ~7 months with an `npx <name> install` fallback installer alongside the plugin path — dual-channel install (marketplace + npx) maximizes reach ([repo](https://github.com/thedotmack/claude-mem)).
